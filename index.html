SupportPilot: AI customer-support agent

A support agent that answers from a knowledge base with citations, looks up orders and opens tickets through tools, and hands off to a human when it isn't sure. Built in five phases, with RAG, agent and red-team evals gating every pull request.

  • RAGpgvector retrieval with cited answers
  • AgentsLangGraph tool calling and an MCP ticket server
  • EvalsRetrieval and answer-quality checks on every PR
Show the details
  • LLM layer: streaming chat over SSE, a provider switch (Ollama, Gemini, Vertex AI, any OpenAI-compatible API), structured output and conversation memory.
  • RAG: hybrid search over pgvector and Postgres full text with reciprocal rank fusion, reranking and cited answers; it says so when the docs don't cover a question.
  • Agent: LangGraph flow that classifies the request, then calls tools for accounts, refunds and escalation; refunds wait for human approval. Tickets go through an MCP server.
  • Production: input guardrails against prompt injection and data leaks, per-call cost and latency logging, a semantic cache and Langfuse tracing.
  • Fine-tuned a small routing model and added a deploy path to a managed cloud AI platform.
  • Runs fully local with Ollama (qwen2.5, nomic-embed-text), with Gemini as an optional hosted model.

Two pieces of the LLM stack you can poke at right here. Both run entirely in your browser with simplified maths, so they show the mechanics without calling a model.

    How RAG picks its context

    Ask a support question. The page scores six help-centre chunks against it, keeps the top two and writes a cited answer. Real systems use dense embeddings; this uses TF-IDF so you can see the scores.

    What a model actually reads

    Type anything to see it split into tokens. Models bill and reason in tokens, not words. This is a rough BPE-style approximation, so counts are close to, not equal to, a real tokenizer.
